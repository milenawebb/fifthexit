- Translations: only the current domain's locale is loaded, returned from the root loader and added to i18next (initAsync: false); never statically import both locale JSONs. Why: keeps the unused language out of the page bundle.
- Below-the-fold homepage sections (portfolio, estimator, booking) are lazy chunks mounted by `LazySection` with reserved min-height; nav anchors target its placeholder id. Why: PageSpeed main-thread and unused-JS savings without layout shift.
- Homepage motion uses shared browser hooks, one reveal observer with lazy-content discovery, viewport-gated animation frames, and CSS reduced-motion overrides; portfolio placeholder and loaded section share responsive height rules. Why: both markets receive identical effects without animation dependencies or layout shifts.
- Market-exclusive chrome (the English footer DBA line and the English navbar Instagram glyph) is gated on the active locale rather than a route, and the social icon keeps a 24px hit area with the standard nav gap. Why: those belong to the US market only, and the fixed hit area and gap hold the accessibility and touch-target audits while the nav compacts.
- Portfolio case studies use the shared CaseStudy layout, localized copy from the active locale, and leaf-owned canonical, hreflang and social-image tags; the root omits duplicate tags for these pages. Why: future case studies retain consistent presentation and independent search previews.
